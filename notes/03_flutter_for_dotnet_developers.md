# Flutter & Dart for .NET Developers: The Rosetta Stone Guide

## Overview

As a **.NET / C# developer**, you already understand object-oriented programming, static typing, async/await, and dependency injection.

However, when entering Flutter, you will notice three immediate differences:

1. **There are no XAML or HTML/CSS files** — UI and styles are written 100% in Dart code.
2. **UI is strictly Declarative** — You don't mutate controls; you mutate state and let the framework rebuild the tree.
3. **Dart syntax has a few unique idioms** — Named constructor parameters, file-level privacy (`_`), and compile-time `const`.

This document translates these core concepts directly into terms you already know.

---

## 1. "Where Does the CSS Come From?" (Styling in Flutter)

In web development, structure is in HTML, behavior is in JS, and presentation is in CSS.
In WPF or .NET MAUI, structure is in XAML, and styles are in `ResourceDictionary` styles.

**In Flutter, styling is composed directly using Dart widgets and theme objects.**

Flutter approaches styling at **three distinct levels**:

```text
┌────────────────────────────────────────────────────────────┐
│ Level 3: Global Theme (ThemeData)                          │
│          App-wide color palette, typography, button themes │
└─────────────────────────────┬──────────────────────────────┘
                              │ inherited by
                              ▼
┌────────────────────────────────────────────────────────────┐
│ Level 2: Structural / Decorator Widgets                    │
│          Padding, Container, Center, SizedBox, Card        │
└─────────────────────────────┬──────────────────────────────┘
                              │ wraps
                              ▼
┌────────────────────────────────────────────────────────────┐
│ Level 1: Inline Widget Properties                          │
│          TextStyle, Icon size/color, Button styleFrom      │
└────────────────────────────────────────────────────────────┘
```

---

### Level 1: Inline Styling (Like inline CSS / local attributes)

You pass styling configuration objects directly into widget constructors:

```dart
Text(
  'Hello World',
  style: TextStyle(
    fontSize: 20.0,
    fontWeight: FontWeight.bold,
    color: Colors.blue,
    letterSpacing: 1.2,
  ),
)
```

---

### Level 2: Structural Widgets as Styling (Margins, Padding, Borders)

In CSS, you set `margin: 16px; padding: 12px; border: 1px solid #ccc;` on an element.
In Flutter, **layout and spacing are widgets themselves**:

#### Padding

```dart
Padding(
  padding: const EdgeInsets.symmetric(horizontal: 16.0, vertical: 8.0),
  child: Text('Spaced content'),
)
```

#### Container (The `<div>` of Flutter)

A `Container` combines sizing, padding, margin, borders, background colors, and border radii:

```dart
Container(
  margin: const EdgeInsets.all(12.0),
  padding: const EdgeInsets.all(16.0),
  decoration: BoxDecoration(
    color: Colors.white,
    borderRadius: BorderRadius.circular(12.0),
    boxShadow: [
      BoxShadow(
        color: Colors.black.withOpacity(0.08),
        blurRadius: 8.0,
        offset: const Offset(0, 4),
      ),
    ],
  ),
  child: const Text('Styled Box'),
)
```

---

### Level 3: Global Theming (`ThemeData`)

- **.NET Parallel:** App-level `Styles.xaml` in MAUI/WPF or CSS Custom Properties (`:root { --primary-color: ... }`).
- In `MyApp` (`lib/main.dart`), you define your app's global theme:
  ```dart
  theme: ThemeData(
    colorScheme: ColorScheme.fromSeed(seedColor: Colors.deepPurple),
    useMaterial3: true,
  )
  ```
- Any widget anywhere in your tree can access this theme using `Theme.of(context)`:

  ```dart
  // Reads the primary color generated by the theme
  color: Theme.of(context).colorScheme.primary

  // Reads the standard headlineMedium typography style
  style: Theme.of(context).textTheme.headlineMedium
  ```

- When you switch between Light and Dark mode, changing `ThemeData` automatically repaints your entire app with zero manual wiring!

| CSS Property                             | Flutter Equivalent                                                     |
| ---------------------------------------- | ---------------------------------------------------------------------- |
| `color: #ff0000;`                        | `TextStyle(color: Colors.red)` or `Color(0xFFFF0000)`                  |
| `font-size: 16px;`                       | `TextStyle(fontSize: 16.0)`                                            |
| `font-weight: bold;`                     | `TextStyle(fontWeight: FontWeight.bold)`                               |
| `padding: 16px;`                         | `Padding(padding: EdgeInsets.all(16.0), child: ...)`                   |
| `margin: 8px 16px;`                      | `Container(margin: EdgeInsets.symmetric(vertical: 8, horizontal: 16))` |

## 2. How Functions & Events Are Called

In C#, you attach event handlers using delegates or event subscriptions:

```csharp
// C# Event Handling
myButton.Click += MyButton_Click;

// Or via XAML Command binding
<Button Command="{Binding IncrementCommand}" />
```

In Dart, **functions are first-class citizens** (equivalent to C# `Action` or `Func<T>`).
You pass functions directly into widget callback parameters (such as `onPressed`, `onChanged`, `onTap`).

### Pattern A: Method Reference (Tear-off)

Used in `lib/main.dart`:

```dart
void _incrementCounter() {
  setState(() {
    _counter++;
  });
}

// In the build method:
FloatingActionButton(
  onPressed: _incrementCounter, // No parentheses! We pass the method reference.
  child: const Icon(Icons.add),
)
```

> **Warning:** Never write `onPressed: _incrementCounter()`. That immediately invokes the method when the widget builds, passing `void` to `onPressed`.

---

### Pattern B: Anonymous Lambda Closure

If you need to pass an argument or run inline logic:

```dart
FloatingActionButton(
  onPressed: () {
    // Equivalent to C# () => { ... }
    _incrementCounter();
  },
  child: const Icon(Icons.add),
)
```

---

### Pattern C: Event with Data (e.g. Checkbox / TextField)

In our upcoming Todo app, a checkbox passes a `bool?` value:

```dart
Checkbox(
  value: todo.isCompleted,
  onChanged: (bool? newValue) {
    // newValue is provided by Flutter when the user taps
    setState(() {
      todo.isCompleted = newValue ?? false;
    });
  },
)
```

## 3. The Big Mental Shift: Declarative UI vs. Imperative UI

### The Imperative Model (Traditional .NET WinForms / WPF Code-Behind)

```csharp
// You manually find the UI element and mutate its properties
void OnUserClicked() {
    _counter++;
    counterLabel.Text = _counter.ToString();
    counterLabel.ForeColor = Color.Red;
}
```

- **Problems:** Synchronization bugs (UI and internal state get out of sync), complex state tracking.

---

### The Declarative Model (Flutter & Modern .NET Blazor / Compose / SwiftUI)

$$\text{UI} = f(\text{State})$$

In Flutter:

1. You store the state in variables (`int _counter = 0;`).
2. You declare what the UI looks like for **any given value of that state**:
   ```dart
   Text('$_counter')
   ```
3. When you want to change the UI, you update the state inside `setState()`:
   ```dart
   setState(() {
     _counter++;
   });
   ```
4. Flutter automatically re-executes `build()`, diffs the new tree against the old tree, and redraws **only the changed pixels**.

## 4. What is `BuildContext`?

When you implement `Widget build(BuildContext context)`, what is that `context`?

- **In .NET terms:** Think of `BuildContext` as a combination of:
  1. An **Element tree node handle** (location of this widget in the visual hierarchy).
  2. A **Service Provider / Scoped DI Container** (`IServiceProvider`).

### Why do you need `context`?

Because widgets are lightweight blueprints, they don't know who their parents are on their own. The `context` gives the widget access to the surrounding environment:

```dart
// 1. Theme lookup (Ambient context / DI)
ThemeData theme = Theme.of(context);

// 2. Screen Dimensions (Media query)
double screenWidth = MediaQuery.of(context).size.width;

// 3. Navigation (Routing)
Navigator.of(context).pushNamed('/details');

// 4. Show a Toast / SnackBar
ScaffoldMessenger.of(context).showSnackBar(
  const SnackBar(content: Text('Task saved!')),
);
```

## 5. Under the Hood: The Three Trees

A common concern for .NET developers is: _"If `build()` is called repeatedly, isn't recreating all these objects terrible for performance and garbage collection?"_

The answer is **No**, because Flutter maintains **Three Parallel Trees**:

```text
1. Widget Tree (Cheap Blueprints)
   [MyApp] -> [MaterialApp] -> [Scaffold] -> [Center] -> [Text("0")]
      │
      ▼ inflates / updates
2. Element Tree (Long-lived Lifecycle Managers)
   [ComponentElement] -> [RenderObjectElement]
      │
      ▼ manages
3. RenderObject Tree (Heavyweight GPU Drawers - Impeller / Skia)
   [RenderView] -> [RenderParagraph] -> draws pixels on screen
```

1. **Widget Tree:** Very lightweight, cheap C-struct-like immutable objects. Discarded and recreated in milliseconds.
2. **Element Tree:** The actual persistent skeleton in memory (like the Virtual DOM in web or Visual Tree in WPF). When a new Widget tree is built, Flutter compares types and keys. If they match, Flutter simply updates the properties on the existing Element rather than recreating it.
3. **RenderObject Tree:** The heavy objects that calculate coordinates, perform layout passes, and issue GPU paint commands. Only re-laid out when geometry or colors actually change.

## 6. Dart vs. C# Language Comparison Cheatsheet

### A. Variables & Mutability

| Concept                | C#                     | Dart                | Notes                                            |
| ---------------------- | ---------------------- | ------------------- | ------------------------------------------------ |
| Type inference         | `var x = 10;`          | `var x = 10;`       | Both statically typed                            |
| Readonly / Assign once | `readonly int x = 10;` | `final int x = 10;` | Initialized at runtime                           |
| Compile-time constant  | `const int x = 10;`    | `const int x = 10;` | Dart allows `const` objects (`const Text('hi')`) |
| Nullable type          | `string? name;`        | `String? name;`     | Both feature sound null-safety                   |
| Null coalescing        | `name ?? "Default"`    | `name ?? 'Default'` | Identical                                        |
| Null assertion         | `name!`                | `name!`             | Tells compiler "trust me, not null"              |

---

### B. Constructors & Parameters

In C#, constructors typically use positional arguments:

```csharp
// C#
public class TodoItem {
    public string Title { get; }
    public bool IsDone { get; }

    public TodoItem(string title, bool isDone = false) {
        Title = title;
        IsDone = isDone;
    }
}
// Calling:
var item = new TodoItem("Buy milk", isDone: false);
```

In Dart, **named parameters** surrounded by `{}` are standard for almost all widgets:

```dart
// Dart
class TodoItem {
  final String title;
  final bool isDone;

  // Constructor with initializing formals (no boilerplate assignment body needed)
  const TodoItem({
    required this.title,
    this.isDone = false,
  });
}

// Calling:
final item = TodoItem(title: 'Buy milk', isDone: false);
```

---

### C. Visibility & Privacy

| C#                             | Dart                                                       |
| ------------------------------ | ---------------------------------------------------------- |
| `public string Title;`         | `String title;` (no keyword needed)                        |
| `private int _counter;`        | `int _counter;` (leading `_` makes it private to the file) |
| `private class InternalHelper` | `class _InternalHelper` (leading `_` on class name)        |

---

### D. Asynchronous Programming

| Feature             | C#                        | Dart                                          |
| ------------------- | ------------------------- | --------------------------------------------- |
| Single async return | `Task<T>`                 | `Future<T>`                                   |
| Async stream return | `IAsyncEnumerable<T>`     | `Stream<T>`                                   |
| Async keyword       | `async` / `await`         | `async` / `await`                             |
| Waiting on async    | `await FetchDataAsync();` | `await fetchData();`                          |
| Delay / Sleep       | `await Task.Delay(1000);` | `await Future.delayed(Duration(seconds: 1));` |

---

### E. Collections & LINQ

| C# LINQ                                   | Dart Collection Methods                           |
| ----------------------------------------- | ------------------------------------------------- |
| `list.Select(x => x.Title)`               | `list.map((x) => x.title)`                        |
| `list.Where(x => x.IsDone)`               | `list.where((x) => x.isDone)`                     |
| `list.FirstOrDefault(x => ...)`           | `list.firstWhere((x) => ..., orElse: () => null)` |
| `list.Any(x => x.IsDone)`                 | `list.any((x) => x.isDone)`                       |
| `list.ToList()`                           | `list.toList()`                                   |
| List literal: `new List<int> { 1, 2, 3 }` | `[1, 2, 3]`                                       |
| Collection-if (Dart superpower):          | `[ if (showButton) ElevatedButton(...) ]`         |
| Spread operator:                          | `[ ...existingList, newItem ]`                    |

## Summary Checklist for Building Flutter Apps

1. **Everything is a Widget:** UI, padding, gestures, themes.
2. **Stateless vs. Stateful:**
   - Doesn't change dynamically? Use `StatelessWidget`.
   - Has internal state that triggers UI updates? Use `StatefulWidget` + `setState()`.
3. **Styling:**
   - Global: `ThemeData` inside `MaterialApp`.
   - Structural: `Padding`, `Container`, `SizedBox`.
   - Text/Icons: `TextStyle`, `IconTheme`.
4. **Events:**
   - Pass function references: `onPressed: _handlePress`.
   - Trigger rebuilds: `setState(() { ... })`.
5. **No XAML / CSS files:** Everything is compiled, type-safe Dart code.
